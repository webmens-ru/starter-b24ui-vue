# Документация полей формы: Калькулятор калитки (Тип 1)

## Общая структура

Форма — многоэтапный мастер (`src/pages/wicket/Type1.vue`). Все состояние хранится в синглтон-composable `useCalculation.ts`. Каждое изменение поля автоматически сохраняется через `saveWicketData()`.

---

## Порядок этапов

```
page1 → page2 → [page2_facade_siding | page2_facade_profnastil]
                      ↓ "Одна сторона": → page5
                      ↓ "Две стороны":  → [page2_yard_siding | page2_yard_profnastil] → page5
page5 → page3 → page6 → page7 → page9
page9 → [page_lock_type если "Есть"] → page10 → page11 → page12
        [page10 напрямую если "Нет"]
```

## Этап 9 — Клиент (`Client.vue`)

> **Частично обязательно.** Валидация через yup, запускается при нажатии "Далее" (`validateAll()`). Живая проверка на blur и при вводе (если поле в состоянии ошибки).

| Ключ в composable | Тип | Обязательное | Правило валидации |
|---|---|---|---|
| `calculation_name` | text | Нет | — |
| `client_name` | text | **Да** | `yup.string().required()` |
| `client_last_name` | text | Нет | — |
| `client_surname` | text | Нет | — |
| `country_code` | text (datalist) | Нет | Должен быть из списка: `+1, +7, +31, +33, +44, +49, +380, +375`; валидация на blur |

| `client_address` | text (автодополнение) | Нет | Автодополнение через API после 3 символов (debounce 300 мс) |
| `client_comment` | textarea | Нет | — |

## Этап 10 — Рассчитать (`End.vue`)

| Действие | Что происходит |

## Указатель полей с влиянием

Все поля, которые оказывают влияние на другие поля или на маршрут навигации, сгруппированы по разделам. Для каждого поля указано — на что именно оно влияет.

### Этап 2 — Заполнение

**Сторона заполнения** (`fill_side`)**:**
- → **Материал заполнения (двор)** (`material_yard_glob`) *(Этап 2)*: видимость + при "Одна сторона" сбрасывается в `null`; при "Две стороны" копируется из "Материал заполнения (фасад)"
- → Маршрут: значение "Одна сторона" полностью пропускает под-этапы выбора материала для двора

**Материал заполнения (фасад)** (`material_facade_glob`)**:**
- → Маршрут: "Сайдинг" → этап выбора сайдинга для фасада; "Профлист" → этап выбора профлиста для фасада

**Материал заполнения (двор)** (`material_yard_glob`)**:**
- → Маршрут: "Сайдинг" → этап выбора сайдинга для двора; "Профлист" → этап выбора профлиста для двора

---

### Этап 3 — Столбы / Вариант открытия / Перемычка

**Наличие столбов** (`nalichie_stolbov_id`)**:**
- → **Столб / сортамент** (`stolb_id`) *(Этап 3)*: видимость — выпадающий список столба отображается только при значении "Со столбами"

**Вариант открытия** (`opening_option_id`)**:**
- → **Перемычка / положение** (`peremichka_polozheniye_id`) *(Этап 3)*: видимость + перезагрузка списка вариантов при каждом изменении
- → **Перемычка / сортамент** (`peremichka_sortament_id`) *(Этап 3)*: сбрасывается при каждой смене варианта открытия
- → Изображения типов щита *(Этап 4)*: id 1 или 4 → изображения "правая сторона"; id 2 или 3 → "левая сторона"

**Перемычка / положение** (`peremichka_polozheniye_id`)**:**
- → **Перемычка / сортамент** (`peremichka_sortament_id`) *(Этап 3)*: видимость — выпадающий список скрыт при выборе "Без перемычки"

---

### Этап 4 — Тип щита

**Тип щита** (`shield_type`)**:**
- → **Высота верхней части** (`height_top_part`) *(Этап 4)*: видимость — только при "Тип 3"; при смене типа сбрасывается в "0"
- → **Высота нижней части** (`height_lower_part`) *(Этап 4)*: видимость — при "Тип 2" и "Тип 3"; при смене типа сбрасывается в "0"
- → **Ширина боковой решётки** (`width_side_part`) *(Этап 4)*: видимость — только при "Тип 4"; при смене типа сбрасывается в "0"
- → **Расположение решётки** (`grille_location`) *(Этап 4)*: видимость — только при "Тип 4"; при смене типа сбрасывается

---

### Этап 7 — Комплект замка

**Замок есть/нет** (`is_there_lock_id`)**:**
- → **Замок предоставляет** (`provides_lock`) *(Этап 7)*: видимость — только при "Есть"; при "Нет" сохраняется как `null`
- → **Врезку замка выполняет** (`lock_installer`) *(Этап 7)*: видимость — только при "Есть"; при "Нет" сохраняется как `null`
- → **Кабель для э/м замка** (`is_there_cable`) *(Этап 7)*: видимость — только при "Есть"; при "Нет" сохраняется как `null`
- → Маршрут: "Есть" → открывается этап "Тип замка" (7а); "Нет" → этап 7а пропускается, переход сразу на этап 8

---

### Этап 8 — Дополнительная ручка (скоба)

**Дополнительная ручка** (`is_there_pen_id`)**:**
- → **Ручку предоставляет** (`pen_provided`) *(Этап 8)*: видимость — только при "Будет"; при "Не будет" сохраняется как `null`
- → **Ручку устанавливает** (`pen_installed`) *(Этап 8)*: видимость — только при "Будет"; при "Не будет" сохраняется как `null`
- → **Цвет ручки** (`pen_color`) *(Этап 8)*: видимость — только при "Будет"; при "Не будет" сохраняется как `null`

## Глобальный пересчёт

Если `calc.price_retail.value` уже установлен (был произведён хотя бы один расчёт), каждое изменение любого поля автоматически вызывает `recalculate()` после `saveWicketData()`. Это обновляет сводную панель в правом сайдбаре в режиме реального времени.

Панель сводки (`CalculateTable`) слушает DOM-событие `dataUpdated`, которое диспатчится внутри `updateOrCreateBlock()` и `removeAllBlocksExcept()`.
