# Инструкции для frontend starter-b24ui-vue

## Названия не являются идентификаторами или бизнес-признаками

- Запрещено управлять расчётами, валидацией, переходами, фильтрацией связанных справочников, выбором материалов или геометрией через отображаемые `name/title/label`.
- Запрещены бизнес-сравнения, `switch`, поиск подстрок и регулярные выражения по названиям категорий, покрытий, материалов, направлений и других записей. Константа с названием не решает проблему.
- В `v-model`, `value`, option IDs и API-параметрах использовать реальные ID либо стабильные контрактные коды. Не присваивать `id: item.name`. Подписи хранить отдельно от сохраняемого значения.
- Поведение брать из явных признаков API. Размеры, стороны и направления получать структурированными полями, не вычислять из текста названий. Если API не передаёт нужный признак, дорабатывать контракт, а не угадывать его по названию.
- Сводки обновлять и связывать с PDF/API через стабильные `blockCode/paramCode`, отдельно от русских заголовков.
- Допустимы отображение, текстовый поиск и сортировка по названию; документированный импорт разрешает имена в ID на границе. Исторические строки допускаются только в изолированном адаптере совместимости, без новых зависимостей от них.
- Не расширять уже существующие зависимости от названий. Менять их согласованными этапами вместе с бэкендом, учитывая старые заказы и снимки.
- При изменении бизнес-логики проверять: переименование подписи при прежних ID/кодах/признаках не меняет поведение. Существенные сценарии закреплять регрессионными проверками.
- Фиксированный ID справочника не является заменой признака роли: получать отдельные свойства/коды API. Динамические FK и технические modelId/status/page codes допустимы.
- Перед завершением изменений запускать `npm run check:policy`; он также входит в `npm run test:run`. Guard использует имеющийся TypeScript parser, проверяет script и выражения Vue-привязок, включая callbacks/switch и известные ID-ветвления.
- Исключения перечислены точными путями в `scripts/check-name-policy.mjs`. Новое имя файла `legacy…` автоматически ничего не разрешает; исключение требует причины и review, а новая бизнес-логика не должна маскироваться под адаптер.
  В `FillingAppearanceFields.vue` только `setManufacturer`/`setColor` разрешают сравнение сохранённой подписи для обновления отображаемых данных при авторитетном FK; это не классификация товара. Остальные функции файла проверяются.
- Guard не заменяет review и rename-тесты: он не доказывает отсутствие зависимостей через произвольные алиасы/поток данных, динамические вызовы и все варианты выражений шаблона. Запрет распространяется и на то, что статический анализ не обнаружил.

## Рабочие файлы

- Исходники находятся в `src/`; `dist/` — результат сборки, вручную его не редактировать.
- Контракт API менять согласованно с backend `8-calc.doorhan-krd`.
